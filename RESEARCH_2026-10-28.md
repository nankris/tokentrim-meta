# TokenTrim research notes, Oct 28 2026

What recent work on agent memory, prompt caching, context compaction, tool-output trimming and model routing means for TokenTrim. All sources were opened on Oct 28 2026. The numbers quoted are the authors' own claims, not our measurements.

## Ranked adopt / skip table

Rank is by expected effect on **billed dollars per passed task** for our setup (Muse Spark/Wonder, 40 small Python tasks, ~1 week left), weighed against build cost and risk.

## What each source says that matters to us

**[1] Anthropic, "Lessons from building Claude Code: Prompt caching is everything" (Apr 30 2026).**
- Prefix matching means any change invalidates everything after it.
- Order the prompt as: static system and tools → project context → session context → messages.
- Send updates as messages, not prompt edits.
- **Don't change models mid-session.** Caches are per model. 100k tokens into an Opus conversation, switching to Haiku for an easy question costs *more* than letting Opus answer, because Haiku has to rebuild the cache. To switch models, hand off a short message to a subagent.
- Never add or remove tools mid-session. Use stubs with deferred loading instead.
- Monitor the cache hit rate like uptime.
- *For TokenTrim:* this directly undermines naive per-step Spark↔Wonder routing. Every switch re-bills the whole context at the new model's uncached rate. The router now has to pass a switch-cost check, and the simulator models a separate cache per model so the effect shows up in the numbers.

**[2] Claude Code docs, "How Claude Code uses prompt caching".**
- Lists the actions that invalidate the cache: model switch, MCP/tool changes, compaction, effort changes.
- Lists the actions that keep it: appending, rewinding.
- Compaction is a single deliberate cache break, so do it at natural breaks.
- *For TokenTrim:* compaction happens at checkpoints, not on every turn.

**[3] Manus, "Context Engineering for AI Agents".**
- The KV-cache hit rate is "the single most important metric" for production agents. Their input-to-output ratio is about 100:1.
- Keep the prefix stable, keep the context append-only, and serialize deterministically (JSON key order).
- Place cache breakpoints explicitly.
- Compression should be restorable, for example by keeping a URL or path.
- *For TokenTrim:* the layout lint, sorted-key serialization and OutputStore pointers come from here.

**[4] vLLM prefix caching notes.**
- Blocks are hashed along a chain from token 0, so a difference at position p invalidates every block from p onward.
- The page includes a table of common hit-rate killers: dates at the top, varying document order, rewritten history.
- *For TokenTrim:* the block-granular cache in the simulator and the lint rules.

**[5] Anthropic pricing and prompt-caching docs.**
- 5-minute write = 1.25× input, 1-hour write = 2×, read = 0.1× (0.05× on Opus/Sonnet 5.5, 0.025× on Fable/Mythos 5.1).
- Minimum cacheable prefix depends on the model (512 to 4,096 tokens).
- Up to 4 explicit breakpoints.
- *For TokenTrim:* optional `cache_write` pricing and breakpoint metadata.

**[6] Meta Model API pricing page (dev.meta.ai, opened Oct 28 2026).**
- Prices confirmed:
  - Wonder: $4.00 input, $0.20 cached, $20.00 output.
  - Spark 1.3: $1.25 input, $0.15 cached, $4.25 output.
  - Contributor: $0.10 input, $0.002 cached, $0.20 output.
- Contributor mode isn't available for Wonder.
- The usage object reports `cached_tokens`.
- No long-context premium.
- Meta's injected steering tokens are not billed.
- Rate limits are 3,000 RPM and 4M TPM per model, and 150 RPM for contributor.
- The page states **no minimum cacheable prefix, no TTL and no cache-write charge.** We have to measure these once credits arrive.
- *For TokenTrim:* the prices in `prices.toml` are now verified against the public page, though not yet against a bill.

**[7] OpenAI prompt caching guide.**
- Caching is automatic for prefixes of at least 1,024 tokens, with hits reported in 128-token increments.
- `prompt_cache_key` improves routing, kept under about 15 requests per minute per key.
- The usage field is `usage.prompt_tokens_details.cached_tokens`.
- *For TokenTrim:* the simulator's defaults, and the proxy should pass a stable cache key through per task.

**[8] JetBrains Research, "The Complexity Trap" (arXiv 2508.21433), SWE-agent on SWE-bench Verified.**
- Simple observation masking cut cost by about 50% versus the raw agent and matched LLM summarization on solve rate.
- A hybrid approach saved a further 7–11%.
- Results come with 95% bootstrap CIs, and there is one notable drop: −9.9% relative solve rate on Gemini 2.5 Flash (thinking).
- *For TokenTrim:* masking is the default. We report pass rate with CIs because masking can hurt some models.

**[9] Anthropic context editing (`clear_tool_uses_20250919`).**
- Configuration options:
  - `trigger`: default 100k input tokens
  - `keep`: last 3 tool uses
  - `clear_at_least`: "helps determine if context clearing is worth breaking your prompt cache"
  - `exclude_tools`
- *For TokenTrim:* the same knobs, plus a break-even calculation in dollars.

**[10] Anthropic cookbook, "memory, compaction, and tool clearing".**
- Clearing is a "sub-transcript" operation that keeps the record of the call and drops the re-fetchable payload.
- Compaction is a lossy whole-transcript summary.
- *For TokenTrim:* the placeholder keeps the tool-call record.

**[11] SWE-Router (arXiv 2607.00053).**
- A prompt-only router hits a Bayes-error floor on SWE tasks. Reading a K-turn partial trajectory from the cheap model improves Route-AUC by at least 12 pp.
- On escalation, the strong model restarts from the original prompt.
- *For TokenTrim:* use the cheap model for exploration and reads, and escalate on visible signals. Restarting the strong model from a compact hand-off avoids paying the cheap model's history on the strong model's uncached rate.

**[12] Databricks MemEx (May 2026).**
- A typed Python kernel holds the tool outputs, and only the printed output enters the context.
- Reported 25–50% less token cost along with accuracy gains.
- *For TokenTrim:* reinforces keeping bulky outputs out of the context behind pointers.

**[13][14] Databricks MemCurrent and Agent Memory (Oct 20 2026).**
- Separates session transcripts from durable memories and consolidates memories offline.
- Reported 31% fewer tokens, 26% faster runs, and 3× pass rate on Databricks' internal benchmark. On public benchmarks it matched full context with about 12× fewer input tokens.
- *For TokenTrim:* future work. It could serve a "repo facts" memory pinned in the stable prefix, but not in this benchmark.

**[15] ACON (Microsoft Research, PMLR 2026).**
- Gradient-free optimization of compression guidelines from paired success/failure trajectories.
- Reported 26–54% lower peak tokens.

**[16][17] SWE-Pruner and SWE-Pruner Pro.**
- Line-level pruning of code reads guided by the agent's goal. Reported 23–54% and up to 39% token savings.

**[18] CodeRescue (arXiv 2607.19338).**
- Withdrawn. Listed only so no one cites it by mistake.

## Implications for the plan (PREP_v2)

1. **Routing granularity.** Per-step model switching can *lose* money once the context is large and cached. Make the router cache-aware: switch only when the projected saving over the remaining steps beats the cost of re-billing the prefix. Prefer switching at phase boundaries (explore on Spark, then edit on Wonder via a compact hand-off), and keep escalation sticky.
2. **Trimming vs caching.** Every trim of old history is a cache break. Trim in batches, only above a threshold, and only when the dollar break-even is positive. Never trim on every turn.
3. **Pre-work for Oct 29–31 (needs credits).** Measure Muse's minimum cacheable prefix, its TTL, whether a cached prefix is shared across `muse-spark-1.3` and `muse-spark-1.2` (it probably isn't), and whether any cache-write premium applies. All of these feed straight into the simulator's parameters.
4. **Claims.** The headline should still be measured dollars. Everything in `results/sim/` is simulation.

## What the offline simulation said (SIMULATION, not measurements)

`bench/simulate.py`, 40 tasks × 3 repeats, seed 42, verified Muse prices, `realistic` scenario. See `results/sim/`.

- **Rank 1 confirmed:** per-step routing with a strong-model planning step saves only 1.7% [0.4, 3.1], because each upgrade re-bills the context cold on Wonder. Cheap-first routing with sticky escalation saves 36.3% on its own. Stacked with the other savers it saves 45.6% [40.1, 51.1], with a pass difference of −4.2 pp [−9.2, 0.0], which is only just non-inferior.
- **The switch check never fired under Muse prices.** Wonder's output costs about 4.7× Spark's, so moving down to a warm or cold Spark always paid. The check matters for close price pairs (see the unit test) and for very large contexts.
- **Rank 5 confirmed:** pruning without the break-even gate costs **13.6% more** than the baseline. With the gate, every drop was deferred, so the saving was 0. At Wonder's $0.20 cached rate, dropping about 3k stale tokens mid-task never repays the cache break within the 4-step horizon.
- **Ranks 4, 6 and 7:** ingest-time log compaction (trim-only) saves 11.6% [10.9, 12.3]. Pass outcomes are unchanged *by assumption*. Raising `trim_penalty` to 3 or 8 pp lowers the stacked saving to 10.9 and 9.9%, and retries absorb the quality hit.
- **Rank 2:** when a client re-serializes tool JSON with unstable key order, the cache hit rate falls to 18% and cost rises 3.5×. The layout saver recovers 71.3%. Against an already cache-friendly baseline it adds 0%, as it should.
- **Rank 9:** setting the minimum cacheable prefix to 0, 1024 or 4096 made no difference, because agent prefixes are 7k+ tokens. An illustrative 1.25× write premium raised baseline cost 15% and lowered the stacked saving to 9.5%.
